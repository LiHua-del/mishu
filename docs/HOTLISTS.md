# 热榜研究

入口：`http://127.0.0.1:8001/hotlists.html`。由首页“热榜研究”进入。

## 使用

频道、分类、官方榜单默认全部，范围限当前平台已接入入口；可缩小到具体榜单。结果按榜单分组，保留频道、分类、来源链接、采集时间、官方统计时间。同书多榜保留各自排名，不生成跨榜总排名。

页面初始读取已保存快照。“联网刷新当前范围”顺序访问官方来源并显示进度，失败保留历史并报告原因。刷新范围越大，用时越长。不会使用原推荐候选池或五分钟缓存。

近 7／30 天是本地观察窗口，按观察上榜天数及平均名次排序，并显示样本覆盖；升降只比较期间首末出现名次。它不是官方周／月榜，不会回补没有采集的历史。跨月的官方月榜不混算。

## 数据和运行

默认数据目录是 `runtime-data/`，可用 `MISHU_DATA_DIR` 指定外部目录。热榜数据库为 `hotlists/snapshots.db`；原始页面为 `hotlists/raw/YYYY-MM-DD/*.html.gz`。每榜每天保存最后成功快照，原始页面保留每次采集，当前没有自动删除策略。备份应包括热榜数据库及原始页面；使用 SQLite 在线备份或停服后复制数据目录。

服务运行时每天北京时间 16 点后采集，首次启动补采空榜，失败至少间隔一小时重试。休眠、关机、停服期间无法采集。此任务由服务内线程执行，不安装系统定时任务或开机自启。容器需安装 tzdata 以支持 Asia/Shanghai，Dockerfile 已包含。

## 版本管理

保留上游 Git 历史与许可证。功能分支为 `feat/hotlists-research`，首个扩展版本标签为 `v0.1.0-hotlists.1`。后续从已发布版本新建分支，检查上游变更后合并，禁止覆盖未提交修改或强推发布历史。

可用 `git log --oneline --decorate` 和 `git show v0.1.0-hotlists.1` 查看版本。回退时先停服、备份数据，再从目标标签创建新分支；不删除运行数据。数据库、日志、个人配置、原始采集页面和小说稿件不提交到代码仓库。
